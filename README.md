# 헬스장 운동기구 실시간 점유·대기 시스템

> 혼잡한 헬스장에서 **누가 어떤 기구를 쓰고 있고, 다음은 누구인지**를 시스템이 정한다.

---

## 1. 무엇을 푸는가

붐비는 시간대의 헬스장에는 이런 일이 있다.

- 기구 앞에 사람이 서 있는데, **쓰는 중인지 쉬는 중인지 모른다.**
- 원판만 꽂아두고 다른 데 가 있는 사람 때문에 **비었는지 알 수 없다.**
- 기다리던 사람이 잠깐 자리를 비운 사이 **다른 사람이 먼저 올라탄다.**
- 한 사람이 **여러 기구를 동시에 잡아둔다.**

전부 "지금 이 기구의 주인이 누구인가" 가 사람들 사이의 암묵적 합의에만 있어서 생기는 문제다. 이 시스템은 그 합의를 **명시적인 점유와 대기열**로 바꾼다.

---

## 2. 어떻게 동작하는가

기구마다 QR 코드가 붙어 있고, 그 QR 은 **그 기구의 화면 주소**를 담고 있다. 찍어서 들어오는 것이 곧 **태깅**이다.

```text
QR 스캔 → /e/TM-01 진입 → 서버가 지금 상태를 보고 정한다
                             ├─ 비어 있다        → 바로 사용 시작
                             ├─ 내 차례가 왔다   → 사용 시작
                             ├─ 남이 쓰는 중     → 대기 등록 (순번 2)
                             ├─ 내가 기다리는 중 → 변화 없음 (내 순번 표시)
                             └─ 내가 쓰는 중     → 변화 없음 (종료 버튼 표시)
```

관리자는 기구를 쓰지 않는다. 관리자가 QR 을 찍으면 판정 없이 그 기구의 관리 화면(현황 · 강제 종료 · 비활성화)이 열린다.

### 세 사람이 러닝머신 하나를 쓰는 동안

| 시각 | 일어난 일 |
|---|---|
| 09:00 | **A** 가 TM-01 을 태깅. 비어 있어 바로 시작. 기다리는 사람이 없는 동안은 시간 제한이 없다 |
| 09:05 | **B** 가 같은 기구를 태깅. 사용 중이므로 **대기 등록, 순번 1**. 대기자가 생겼으므로 A 의 만료 시각이 **09:30**(시작 + 최대 30분)으로 정해진다. B 의 화면에 "약 25분 후" |
| 09:12 | **C** 도 태깅 → **순번 2**. "약 55분 후" |
| 09:28 | A 의 화면에 마감 임박 표시. A 가 **1회(5분) 연장**해 09:35 까지 |
| 09:35 | A 종료. **B 에게 차례가 넘어가고 2분의 유예**가 시작된다 |
| 09:36 | B 가 태깅해 시작. C 의 순번이 1로 당겨진다 |
| 09:50 | B 가 다른 기구(BK-02)를 태깅 → **TM-01 사용 세션은 전환 종료**되고 C 차례 |
| 09:52 | C 가 2분 안에 오지 않았다 → C 는 노쇼로 대기열에서 빠지고 기구는 비어 있음이 된다 |

## 3. 규칙

| 규칙 | 값 | 왜 |
|---|---|---|
| 1인 최대 사용시간 | **기구별로 관리자가 설정** (예: 러닝머신 30분, 스쿼트랙 20분). **대기자가 있을 때만 적용**한다 — 대기자가 없으면 만료·연장·마감 임박 알림 없이 본인이 끝낼 때까지 쓴다 | 기구마다 회전 속도가 다르다. 기다리는 사람이 없으면 끊을 이유가 없다 |
| 초과 중 대기 | 최대 사용시간을 이미 넘겨 쓰는 중에 대기자가 생기면, 만료 시각은 **대기 등록 5분 뒤** | 쓰던 사람에게 정리할 시간을 준다 |
| 마감 임박 | 만료 시각 **5분 전**부터 (만료 시각이 있을 때만) | 연장 단위와 같게 두어, 한 번 연장하면 곧바로 다시 판단할 수 있다 |
| 연장 | 마감 임박 시 **5분, 한 번만**. 대기자가 없으면 만료가 없으므로 연장도 없다 | 기다리는 사람이 있을 때 한 번의 여유만 준다 |
| 노쇼 유예 | 차례가 온 뒤 **2분** | 오지 않는 사람이 대기열을 멈춰 세우지 못하게 한다 |
| 동시 사용 | **1개.** 다른 기구를 태깅하면 이전 사용 세션은 전환 종료 | 여러 기구 잡아두기를 불가능하게 만든다 |
| 차례 호출 중 | 노쇼 유예 동안 그 기구는 **사용 중**으로 보인다. 호출된 회원이 태깅하면 사용 시작(쓰던 기구는 전환 종료), 다른 회원이 태깅하면 대기 등록 | 차례를 받은 사람의 자리를 가로채지 못하게 한다 |
| 호출 시각 | 노쇼 유예는 **앞 사용 세션이 끝난 시각**(앞 대기가 노쇼였다면 그 유예가 끝난 시각)부터 센다. 기록이 늦게 남아도 같다 | 조회가 상태를 바꾸지 않아도 화면과 기록이 같은 답을 내게 한다 |
| 대기 취소 | 본인 대기는 **언제든** 스스로 취소할 수 있다. 기다리는 중에 같은 기구를 다시 태깅해도 취소되지 않는다 — 취소는 화면에서만 | 오지 않을 사람이 대기열에 남아 예상 대기 시간을 늘리지 않게 한다 |
| 동시 대기 | **1개.** 운동 중에도 다른 기구에 대기할 수 있다 | 대기 인원이 실제 나타날 사람과 일치해야 예상 시간이 맞는다 |
| 재대기 제한 | 대기자가 있으면 종료 후 **5분간** 같은 기구에 다시 대기할 수 없다 | 번갈아 대기하며 독점하는 것을 막는다 |
| 예상 대기 시간 | 앞사람 남은 시간 + 앞 대기자 수 × 기구 최대시간 | 근사치임을 화면에 밝힌다 |

**종료되는 경우는 넷이다** — 본인 종료(화면의 종료 버튼), 만료(대기자가 있는 상태에서 만료 시각 경과), 전환 종료(다른 기구를 태깅), 강제 종료(관리자, 또는 기구 비활성화).

## 4. 구성

### 기능

| 이름 | 범위 |
|---|---|
| [`equipment-queue`](docs/features/equipment-queue/README.md) | 태깅 · 사용 세션 · 연장 · 종료 · 대기열 · 차례 호출과 노쇼 |
| [`equipment-catalog`](docs/features/equipment-catalog/README.md) | 기구 등록·수정·최대시간 설정·비활성화, 목록 조회 |

둘 사이에는 계약이 있다 — **비활성화된 기구는 태깅할 수 없고, 비활성화하면 진행 중인 사용 세션은 강제 종료되고 그 기구의 대기는 모두 취소된다.** 판정은 서버가 한다.

### 화면

1. **현황 목록** — 전체 기구의 사용 중 / 비어 있음 / 대기 인원
2. **기구 상세** — QR 이 가리키는 곳. 태깅, 내 순번, 남은 시간, 예상 대기 시간
3. **관리자** — 기구 등록·수정·최대시간·비활성화, 그리고 **강제 종료**

현황은 폴링으로 갱신한다.

### 로그인

일반 회원 몇 명과 관리자 한 명이 시드 데이터로 들어 있다. 관리자는 기구를 쓰지 않는 다른 유형의 회원이다. 세션 기반 로그인만 두고(이 "로그인 세션" 은 사용 세션과 다르다), 미인증이면 로그인 폼을 띄운다.

## 5. 하지 않는 것

| 없는 것 | 대신 |
|---|---|
| 푸시 알림 | 차례가 오면 화면에 표시된다 |
| RFID 하드웨어 | QR 이 담은 URL 로 들어오는 것이 태깅이다 |
| 회원 가입·회원 관리 | 계정은 시드 데이터로 고정 |
| 결제·출입·락커 | 이 시스템이 푸는 문제가 아니다 |
| 통계·혼잡도 이력 | 현재 상태와 예상 대기 시간만 보여준다 |

**만료된 사용 세션을 정리하는 워커를 두지 않는다.** 현황 조회는 "만료 시각이 지났으면 비어 있음" 으로 판단해 보여주고, 실제 종료 기록과 다음 차례 호출은 **다음 태깅 때** 정리한다. 조회가 상태를 바꾸지 않는 대신, 아무도 건드리지 않은 사용 세션은 기록상 사용 중인 채로 남는다.

## 7. 로컬에서 띄우기

MariaDB 는 기기에 직접 설치해 띄운다.

```bash
cp apps/backend/.env apps/backend/.env.local        # 복사해서 실제 접속 정보로 고친다
npm install && npx lefthook install
composer -d apps/backend install
composer -d apps/backend run stan
composer -d apps/backend run test
```
