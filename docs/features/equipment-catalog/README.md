# 기능: 운동기구 관리 (equipment-catalog)

> 상태 값의 뜻은 [`docs/README.md` §2](../../README.md). `planned` = 범위와 최소 보장은 확정, 구현 전.
>
> 용어는 [`domain-glossary.md`](../../business/domain-glossary.md) 를 따른다. 보장 표의 티어를 읽는 법은 [`equipment-queue`](../equipment-queue/README.md) 와 같다 — 한 줄은 **적힌 티어가 모두 초록일 때** 보장된다.

## 왜 · 누가 · 어디까지

- **왜**: 사용·대기의 대상이 되는 기구 목록에 주인이 필요하다. 고장·철거된 기구가 태깅 가능한 채로 남으면 대기열의 보장이 의미를 잃는다.
- **누가**: 관리자(회원 유형 `ADMIN`, 역할 `ROLE_ADMIN`). 관리자는 기구를 쓰지 않는 다른 유형의 회원이다.
- **어디까지(범위)**: 기구 등록 · 이름/종류 수정 · **최대 사용시간 설정** · 비활성화 · 사용 세션 **강제 종료** · 기구 목록 조회, 그리고 그것을 쓰는 **관리자 화면 하나**. 재고·정비 일정·사진 업로드는 범위 밖.
- **왜 이 기능이 따로 있나**: 기능이 하나뿐이면 `FeatureCoverageTest` 의 슬러그 실재성·커버리지 하한 검사가 사실상 동작하지 않는다. 그리고 **기능 사이의 계약**(비활성 기구는 태깅할 수 없다)이 생겨야 "판정의 소유자는 백엔드" 가 실제로 시험된다.

## 최소 보장 — 백엔드 (`apps/backend`, PHPUnit)

`#[Feature('equipment-catalog')]` 라벨이 붙은 테스트가 보증한다.

| # | 보장 | 티어 |
|---|---|---|
| C1 | **관리자가 아니면 관리 조작(등록·수정·비활성화·강제 종료)이 거부된다** — 거부 사유는 `admin_only` | T3 |
| C2 | **같은 기구 코드의 기구는 두 번 등록되지 않는다.** 삭제된 기구의 코드도 다시 쓸 수 없다 — 거부 사유는 `duplicate_equipment_code` (DB 유니크 제약이 최종 보증) | T3 |
| C3 | **비활성 기구는 태깅할 수 없다** — 거부 사유는 `equipment_inactive` | T1 · T2 |
| C4 | **비활성화하면 진행 중인 사용 세션은 강제 종료되고 그 기구의 대기는 모두 취소된다.** 사용·대기 이력은 기록으로 남는다 | T2 · T3 |
| C5 | **현황 목록에는 활성 기구만, 관리자의 기구 목록에는 비활성 기구도 나온다** | T2 |

> C3·C4 가 `equipment-queue` 와의 계약이다. 판정은 **여기(백엔드)** 에서 하고, 대기열 기능도 프론트도 그 결과를 받기만 한다.
>
> C1 이 T3 뿐인 이유: 관리자 여부는 도메인이 판정하지 않는다. Symfony Security 의 `access_control` 이 경로(`/api/admin`)와 역할로 막는다([`backend.md`](../../architecture/backend.md) §5). 그래서 실제 HTTP 요청으로만 검증된다.

### 보장에서 뺀 것 — 왜 최소가 아닌가

| 규칙 | 빼는 이유 |
|---|---|
| 강제 종료 단독(관리자가 한 세션을 끝냄) | C4 가 같은 경로(강제 종료 + 종료한 관리자 기록)를 덮는다. 종료 기록의 불변식(강제 종료에만 관리자가 있다)은 엔티티 T1 이 본다 |
| 이름·종류·최대 사용시간 수정 | 틀려도 다른 보장을 깨지 않는다. 최대 사용시간이 만료 시각에 쓰이는 방식은 `equipment-queue` Q3 의 몫이다 |

## 최소 보장 — 프론트 (`apps/frontend`, Vitest)

- 비활성 기구는 현황 목록에 나타나지 않는다
- 관리자가 아니면 등록·비활성화·강제 종료 조작을 렌더하지 않는다 (권한은 서버가 최종 판단)
- 서버가 `equipment_inactive` 로 거부하면 그 사유를 그대로 노출한다 — 프론트가 활성 여부를 다시 판단하지 않는다

> 첫 줄은 "거부를 미리 줄이는 편의" 이지 규칙의 출처가 아니다. 목록이 낡아 비활성 기구가 보이더라도, 최종 판정은 서버 응답으로 수렴시킨다([`api-contract.md`](../../architecture/api-contract.md) §7).
