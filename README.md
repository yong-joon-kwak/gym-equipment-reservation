# 헬스장 운동기구 실시간 점유·대기 시스템

> 혼잡한 헬스장에서 **누가 어떤 기구를 쓰고 있고, 다음은 누구인지**를 시스템이 정한다.

---

## 1. 무엇을 푸는가

붐비는 시간대의 헬스장에는 이런 일이 있다.

- 기구 앞에 사람이 서 있는데, **쓰는 중인지 쉬는 중인지 모른다.**
- 원판만 꽂아두고 다른 데 가 있는 사람 때문에 **비었는지 알 수 없다.**
- 기다리던 사람이 잠깐 자리를 비운 사이 **다른 사람이 먼저 올라탄다.**
- 한 사람이 **여러 기구를 동시에 잡아둔다.**

전부 "지금 이 기구의 주인이 누구인가" 가 사람들 사이의 암묵적 합의에만 있어서 생기는 문제다. 이 시스템은 그 합의를 **명시적인 점유와 대기열**로 바꾼다.

---

## 2. 어떻게 동작하는가

기구마다 QR 코드가 붙어 있고, 그 QR 은 **그 기구의 화면 주소**를 담고 있다. 찍어서 들어오는 것이 곧 **태깅**이다.

```text
QR 스캔 → /e/TM-01 진입 → 서버가 지금 상태를 보고 정한다
                             ├─ 비어 있다        → 바로 사용 시작
                             ├─ 남이 쓰는 중     → 대기열 등록 (당신은 2번)
                             └─ 내가 쓰는 중     → 사용 종료
```

### 세 사람이 러닝머신 하나를 쓰는 동안

| 시각 | 일어난 일 |
|---|---|
| 09:00 | **A** 가 TM-01 을 태깅. 비어 있어 바로 시작. 최대 30분이므로 09:30 까지 |
| 09:05 | **B** 가 같은 기구를 태깅. 사용 중이므로 **대기 1번**. 화면에 "약 25분 후" |
| 09:12 | **C** 도 태깅 → **대기 2번**. "약 55분 후" |
| 09:28 | A 의 화면에 마감 임박 표시. **대기자가 있으므로 연장은 1회(5분)만** 가능 |
| 09:35 | A 종료. **B 에게 차례가 넘어가고 2분의 유예**가 시작된다 |
| 09:36 | B 가 태깅해 시작. C 는 대기 1번으로 당겨진다 |
| 09:50 | B 가 다른 기구(BK-02)를 태깅 → **TM-01 사용은 자동으로 종료**되고 C 차례 |
| 09:52 | C 가 2분 안에 오지 않았다 → C 는 큐에서 빠지고 기구는 빈 상태가 된다 |

## 3. 규칙

| 규칙 | 값 | 왜 |
|---|---|---|
| 1인 최대 사용시간 | **기구별로 관리자가 설정** (예: 러닝머신 30분, 스쿼트랙 20분) | 기구마다 회전 속도가 다르다 |
| 연장 | 마감 임박 시 **5분 단위**. 대기자가 있으면 **1회만**, 없으면 제한 없음 | 줄이 없을 때까지 재촉하지 않는다 |
| 노쇼 유예 | 차례가 온 뒤 **2분** | 오지 않는 사람이 큐를 멈춰 세우지 못하게 한다 |
| 동시 점유 | **1개.** 다른 기구를 태깅하면 이전 사용은 자동 종료 | 여러 기구 잡아두기를 불가능하게 만든다 |
| 동시 대기 | **1개.** 운동 중에도 다른 기구에 줄을 설 수 있다 | 대기 인원이 실제 나타날 사람과 일치해야 예상 시간이 맞는다 |
| 재등록 | 대기자가 있으면 종료 후 **5분간** 같은 기구에 다시 줄을 설 수 없다 | 번갈아 줄을 서며 독점하는 것을 막는다 |
| 예상 대기 시간 | 앞사람 남은 시간 + 앞 대기자 수 × 기구 최대시간 | 근사치임을 화면에 밝힌다 |

**종료되는 경우는 셋이다** — 본인이 종료하거나, 최대시간이 지나거나, 다른 기구를 태깅하거나.

## 4. 구성

### 기능

| 이름 | 범위 |
|---|---|
| `equipment-queue` | 태깅 · 사용 세션 · 연장 · 종료 · 대기열 · 차례 호출과 노쇼 |
| [`equipment-catalog`](docs/features/equipment-catalog/README.md) | 기구 등록·수정·최대시간 설정·비활성화, 목록 조회 |

둘 사이에는 계약이 있다 — **비활성화된 기구는 태깅할 수 없고, 비활성화하면 그 기구의 대기열은 취소된다.** 판정은 서버가 한다.

### 화면

1. **현황 목록** — 전체 기구의 사용 중 / 비어 있음 / 대기 인원
2. **기구 상세** — QR 이 가리키는 곳. 태깅, 내 순번, 남은 시간, 예상 대기 시간
3. **관리자** — 기구 등록·수정·최대시간·비활성화, 그리고 **강제 종료**

현황은 폴링으로 갱신한다.

### 로그인

회원 몇 명과 관리자 한 명이 시드 데이터로 들어 있다. 세션 기반 로그인만 두고, 미인증이면 로그인 폼을 띄운다.

## 5. 하지 않는 것

| 없는 것 | 대신 |
|---|---|
| 푸시 알림 | 차례가 오면 화면에 표시된다 |
| RFID 하드웨어 | QR 이 담은 URL 로 들어오는 것이 태깅이다 |
| 회원 가입·회원 관리 | 계정은 시드 데이터로 고정 |
| 결제·출입·락커 | 이 시스템이 푸는 문제가 아니다 |
| 통계·혼잡도 이력 | 현재 상태와 예상 대기 시간만 보여준다 |

**시간이 지난 세션을 정리하는 워커를 두지 않는다.** 현황 조회는 "만료 시각이 지났으면 빈 기구" 로 판단해 보여주고, 실제 종료 기록과 다음 사람 호출은 **다음 태깅 때** 정리한다. 조회가 상태를 바꾸지 않는 대신, 아무도 건드리지 않은 세션은 사용 중인 채로 남는다.

## 7. 로컬에서 띄우기

MariaDB 는 기기에 직접 설치해 띄운다.

```bash
cp apps/backend/.env apps/backend/.env.local        # 복사해서 실제 접속 정보로 고친다
npm install && npx lefthook install
composer -d apps/backend install
composer -d apps/backend run stan
composer -d apps/backend run test
```
