# 기능: 운동기구 예약 (equipment-reservation)

> 상태 값의 뜻은 [`docs/README.md` §2](../../README.md). `planned` = 범위와 최소 보장은 확정, 구현 전.

## 왜 · 누가 · 어디까지

- **왜**: 회원이 헬스장 운동기구를 시간 단위로 겹치지 않게 예약한다.
- **누가**: 회원(예약 소유자). 실서비스 인증은 범위 밖 — 데모는 `X-Member-Id` 헤더.
- **어디까지(범위)**: 임시 점유(HELD) → 확정/취소, 기구·회원 겹침 방지, 한도, 감사 이력, 그리고 그 흐름을 쓰는 **예약 화면 하나**. 결제·좌석 지도·알림·만료 배치 스케줄러는 범위 밖.
- **옆 기능과의 경계**: 어떤 기구가 예약 가능한가는 [`equipment-catalog`](../equipment-catalog/README.md) 가 정한다. 이 기능은 그 결과를 입력으로 받는다.

## 최소 보장 — 백엔드 (`apps/backend`, PHPUnit)

`#[Feature('equipment-reservation')]` 라벨이 붙은 테스트가 보증한다. 괄호는 티어([`test-as-specification.md` §2](../../coding/test-as-specification.md)).

| 보장 | 티어 |
|---|---|
| 비어 있는 기구·시간은 점유(HELD)되고, 겹치면 거부되며, 취소하면 다시 예약할 수 있다 | T1 · T3 |
| 과거 시간 · 그리드(정시·고정 길이)를 벗어난 슬롯 · 회원 한도 초과 · 본인 시간 겹침은 거부된다 | T1 |
| 남의 예약은 취소할 수 없다 | T1 · T2 |
| HELD 만 확정할 수 있고, 만료된 홀드는 확정할 수 없다. 모든 전이는 이력으로 남는다 | T1 · T2 |
| 같은 활성 슬롯의 중복 저장은 DB 유니크 제약이 막는다 (동시성 최종 보증) | T3 |

## 최소 보장 — 프론트 (`apps/frontend`, Vitest)

프론트는 규칙의 소유자가 아니다. 계약(타입·거부 사유)을 지키는지만 본다.

- 그리드에 맞지 않는 슬롯이면 점유 버튼이 비활성이다
- 서버가 거부(409/422)하면 거부 사유(reason)를 그대로 노출한다 — 프론트가 규칙을 다시 판단하지 않는다
- 내 예약이 아니면 취소 버튼을 렌더하지 않는다 (권한은 서버가 최종 판단)
- 점유 성공 시 목록을 낙관적으로 갱신하고 서버 응답으로 상태를 수렴시킨다

> 나머지(화면 경로·목록 정렬 UX 등)는 최소 보장이 아니므로 테스트로 옮기지 않는다.
